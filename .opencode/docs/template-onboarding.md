# Template Onboarding Maintainer Rehearsals

This is a source-repository maintainer document, not a project outcome or an asset to copy into destinations. The goal-oriented-design reference tree/proof/index seeds remain intentionally uninitialized. This template repository retains no unit-test suite or static test harness. Read-only one-shot static review and manual rehearsal evidence have narrow scope: neither proves real agent-led installation, model availability, browser operation, runtime compatibility, authentication, container build, or application behavior.

For a change that warrants it, manually rehearse in disposable, isolated destinations and record source commit, exact commands, observed results, and cleanup ownership. Do not use a real user's project or credentials. Do not persist fixtures, harnesses, or test artifacts. Keep any separately approved root-devcontainer work within its existing explicit command and approval gates.

## Required manual scenarios

1. **New/empty destination:** source URL resolves to a pinned commit outside destination; original product goal is preserved verbatim; missing stack/commands remain unknown until asked/evidenced; no application scaffold appears without explicit product-scope and choice approval; install/restart/fresh-session and default `/devcontainer` ordering are respected; setup record has revision permalink and accurate independent statuses.
2. **Existing app, first adoption:** uncommitted/staged user work is preserved; established architecture and actual goal conflicts are surfaced; existing meaningful permission/security policy is not broadly removed without approval; valid existing devcontainer is retained/adapted rather than regenerated; no global tools/runtime/auth/session changes occur silently; relocated command/skill/doc references resolve.
3. **Existing installation update:** prior setup record and approved goals survive; no `/init-goals` rerun, global Playwright reinstall, or repeated environment work occurs; the native V2 source config/agent shapes merge only with exact-release review and approval; a V1 destination keeps active config/agents until a separately approved runtime upgrade; source and target authorship uncertainty is reported; new environment choices/blockers update the record without forced migration. Preserve meaningful destination permission asks/denials rather than clearing them indiscriminately.
4. **Environment exception:** preference-only skip prompts for specifics; concrete platform/security/toolchain constraint is assessed without arbitrary veto; alternative and tradeoffs are documented and user-confirmed; unresolved decision remains pending. Verify credential/session-copy and destructive changes remain separate approvals.
5. **Source integrity:** wrong/moving/unavailable source, dirty unapproved source, or unverifiable revision stops before writes. Exact repository+commit permalink and source path for end-to-end runner follow-up are constructed from recorded provenance, not floating URLs. No source `.git`, README, or `.devcontainer` is copied as application content.
6. **Assets versus actual features:** a destination has current council/container commands and guides but neither a generated council nor container setup. Update reports assets available and features absent, preserves unrelated readiness, and gives conditional `/init-council <evidence-based subject or ambition>` and `/devcontainer` prompts only after compatible staging and command/agent availability; it invokes neither. A confirmed viable environment alternative and an explicitly deferred optional council are recorded without false defects or unrelated blockers.
7. **Partial setup and adapted-current state:** a partially generated council/container is classified incomplete and the matching existing command is offered for reconciliation rather than blindly restarted or overwritten. A behaviorally adequate renamed/adapted council and valid customized environment are found through the path map and classified adapted-current; update retains them despite textual differences and performs no unnecessary changes.
8. **Council coverage and source orientation:** give an existing project a stale/inadequate mandate, changed dependency/integration, and no expert with inspected source familiarity. Update identifies concrete coverage gaps and a justified proposed addition/update without automatic pruning/renaming; for an existing codebase it requires substantive read-only source orientation evidence in current notes, not merely an architect title or docs. If no manager is active/in scope, report exact outstanding note refresh and the explicit `/init-council` continuation without claiming publication.
9. **Safe container repair versus protected migration:** present a compatible, non-destructive file-only correction to an existing config/script alongside a proposed runtime migration, pin bump, changed auth mode, volume identity change, or destructive reset. The reviewed update may plan/apply only the bounded compatible file repair through its proper owner; it preserves local service/tool/container choices and data, and leaves protected work for the `/devcontainer`/implementation continuation and existing approvals. It runs no container operation and reports refresh incomplete until repair is checked.
10. **Unknown provenance and local improvement:** provide an existing setup with unknown baseline and a plausible local improvement. Update uses two-way comparison, marks authorship uncertain, preserves the improvement, and reports unknown readiness as unknown rather than outdated solely because evidence is unverified.
11. **No source code yet:** initialize/reassess a project with no implementation entrypoints. Council source orientation remains pending with no invented architecture findings; the condition is revisited when source exists, while online-first subject research remains distinct.

For focused one-shot review, inspect only the changed contracts and relevant navigation/link targets: destination classification and approval gates, exception requirements, preservation of existing state, revision-pinned source references, and the exclusion of source-only maintainer assets from distribution. A real rehearsal still requires independent scrutiny and cleanup. Report static-review and rehearsal proof gaps accurately; do not convert this checklist into a persisted unit-test suite.
